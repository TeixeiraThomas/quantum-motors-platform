========================================================================
1) OBJECTIF GLOBAL (30 secondes)
========================================================================
Notre objectif etait de reprendre une application legacy et de livrer:
- une infra clusterisee automatisable par Ansible
- une chaine CI/CD complete avec deploiement preprod puis prod blue/green
- un reverse proxy pour exposer les services par domaines
- une collecte centralisee des logs
- une base de donnees persistante (NFS)

Technos utilisees:
- Docker Swarm
- Ansible
- GitLab + GitLab CI
- Traefik
- Loki + Grafana Alloy + Grafana
- Node.js / Next.js / MariaDB

4) PIPELINE CI/CD (1 minute)
========================================================================
Stages definis dans .gitlab-ci.yml:
1. test
2. build
3. deploy_preprod
4. test_preprod
5. deploy_green
6. test_green
7. switch_prod

Logique respectee:
- tests unitaires/lint avant tout deploiement
- build/push images seulement si tests OK
- deploiement preprod puis smoke test preprod
- sur main: deploiement prod green + smoke test green
- bascule blue -> green seulement si tests green OK

========================================================================
7) JUSTIFICATION DES CHOIX (Q/R rapide)
========================================================================
Pourquoi Swarm (et pas Kubernetes)?
- plus simple a operer pour un POC sur 3 noeuds avec contraintes temps
- suffisant pour overlay networks, services replicas, blue/green

Pourquoi Traefik?
- routage par labels Docker
- bon support des domaines front/api et blue/green

Pourquoi Loki/Alloy/Grafana?
- collecte simple de logs conteneurs sans modifier les apps
- visu centralisee exploitable en exploitation

Pourquoi GitLab hors cluster (VM4)?
- conforme au sujet (bare metal sur VM4)
